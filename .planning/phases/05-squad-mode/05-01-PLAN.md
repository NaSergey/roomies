private async assertParticipant(chatId: number, userId: number): Promise<void> {

    where: { id: chatId },
    include: { match: true },
  });

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP request → SquadController | Client-supplied squadId, recipientId, inviteId, action cross here; all are untrusted |
| JWT token → user.id | All authorization derives from the verified JWT sub claim; never trust user id from request body |
| SquadService → Prisma | Business logic enforces squad membership and invite ownership before mutations |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Elevation of Privilege | POST /squads/:id/invites | mitigate | assertLeader() throws 403 if requester is not squad leader |
| T-05-02 | Elevation of Privilege | PATCH /squads/invites/:inviteId/respond | mitigate | respondInvite() checks invite.recipientId === userId before accepting; throws 403 otherwise |
| T-05-03 | Tampering | PATCH respond action field | mitigate | @IsIn(['accept', 'decline']) on RespondInviteDto via class-validator |
| T-05-04 | Tampering | POST /squads/:id/invites recipientId | mitigate | @IsInt() @IsPositive() on InviteMemberDto; service additionally verifies recipientId is a real match |
| T-05-05 | Denial of Service | GET /squads/feed — large result set | accept | take: 20 hard limit on Prisma query; acceptable for MVP scale |
| T-05-06 | Elevation of Privilege | POST /squads — join while already in squad | mitigate | createSquad() queries squadMember where squad.isActive=true before creation; throws 400 |
| T-05-07 | Elevation of Privilege | GET /squads/me — route ordering | mitigate | getMySquad declared before parameterised routes so NestJS does not treat 'me' as a numeric :id |
| T-05-SC | Tampering | npm installs | accept | No new npm packages added in this plan; existing class-validator and Prisma used |
