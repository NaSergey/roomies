Implement `async getFeed(userId: number)`:

const me = await this.prisma.user.findUniqueOrThrow({

const swiped = await this.prisma.swipe.findMany({
  where: { actorId: userId },

})
const swipedIds = swiped.map(s => s.targetId)

Step 3 — Get compatible scenario list (per CONTEXT.md decision):
- `looking_housing_roomie` → compatible with: `['looking_housing_roomie', 'has_housing_seeking_roomie']`
- `has_housing_seeking_roomie` → compatible with: `['looking_housing_roomie', 'has_housing_seeking_roomie']`
- `looking_roomie_find_housing` → compatible with: `['looking_roomie_find_housing']`
- `squad` → compatible with: `['squad']`

Derive this from a static map object inside the method. The map must be exhaustive — every ScenarioType key must have an entry so that 'squad' maps exclusively to ['squad'] (not to any housing scenario).

Step 4 — Query candidates from DB:
```
const candidates = await this.prisma.user.findMany({
  where: {
    id: { not: userId, notIn: swipedIds },
    cityId: me.cityId ?? -1,
    scenario: { in: compatibleScenarios },
    onboardingCompleted: true,
    isActive: true,
  },
  select: {
    id, name, scenario,
    budgetMin, budgetMax,
    smokingOk, petsOk,
    noiseLevel, cleanliness, sleepSchedule, socialLevel, workFromHome,
    photos: { select: { url: true }, orderBy: { displayOrder: 'asc' }, take: 3 },
    vibeTags: { select: { tag: { select: { id: true, label: true } } } },
    districts: { select: { district: { select: { id: true, name: true } } } },
  },
  take: 100,
})
```

Step 5 — Score each candidate (on-the-fly, per D-02 decision):

Hard filter function `hasHardConflict(me, candidate)` returns `true` if:
- `me.budgetMax != null && candidate.budgetMin != null && me.budgetMax < candidate.budgetMin` OR `me.budgetMin != null && candidate.budgetMax != null && me.budgetMin > candidate.budgetMax`
- `!me.smokingOk && candidate.smokingOk` OR `me.smokingOk && !candidate.smokingOk` — only conflicts if one party explicitly prohibits (smokingOk=false means "no smoking required")
- `!me.petsOk && candidate.petsOk` OR `me.petsOk && !candidate.petsOk`

NOTE per CONTEXT.md: `smokingOk=false` means "no smoking allowed". Conflict = `!me.smokingOk && candidate.smokingOk` (I require no smoking but candidate is OK with it) AND vice versa (`!candidate.smokingOk && me.smokingOk`). Same logic for petsOk.

Lifestyle score function `computeLifestyleScore(me, candidate)` returns `number` (0.0–1.0):
- Collect pairs of non-null scales: for each of [noiseLevel, cleanliness, sleepSchedule, socialLevel, workFromHome], if both me and candidate have a non-null value, compute `|me.scale - candidate.scale|`
- If no valid pairs exist, return `0.5` (neutral score, cannot compute)
- score = `1 - (sum of diffs / count of pairs)`
- Convert Prisma Decimal to number with `Number(val)` before arithmetic

Final score logic:
- If `hasHardConflict(me, candidate)` → skip (do not include in output)
- Else: `matchScore = computeLifestyleScore(me, candidate)`, `lifestyleScore = matchScore`, `hardScore = 1.0`

Step 6 — Filter out hard-conflict candidates, sort by matchScore descending, take first 20.

Step 7 — Map to response shape:
```typescript
return scoredCandidates.map(c => ({
  id: c.id,
  name: c.name,
  scenario: c.scenario,

  lifestyleScales: {
    noiseLevel: c.noiseLevel ? Number(c.noiseLevel) : null,

    sleepSchedule: c.sleepSchedule ? Number(c.sleepSchedule) : null,

  },
  matchScore: c._matchScore,  // internal field from scoring step
}))
```

Note: add `_matchScore: number` as an internal property during scoring before the final map.

Step 4 — Check for mutual like (only on like/super_like actions):
```typescript
if (dto.action === 'like' || dto.action === 'super_like') {
  const reverseSwipe = await this.prisma.swipe.findFirst({
    where: {
      actorId: dto.targetId,
      targetId: actorId,
      action: { in: ['like', 'super_like'] }
    }
  });

  if (reverseSwipe) {
    // ENFORCE INVARIANT: user1Id < user2Id
    const user1Id = Math.min(actorId, dto.targetId);
    const user2Id = Math.max(actorId, dto.targetId);

    const match = await this.prisma.match.create({
      data: {
        user1Id,
        user2Id,
        matchScore: 0.5,        // placeholder — not computed here
        hardScore: 1.0,
        lifestyleScore: null,
        vibeScore: null,
        behavioralScore: null,
      }
    });

    return { matched: true, matchId: match.id };
  }
}

return { matched: false };
```

Note: matchScore is set to 0.5 placeholder in the Match record because computing it here would require re-running the scoring algorithm. The feed already computes and exposes the score for display; the Match row is primarily for the mutual-like relationship record. If a future phase pre-computes scores, this value can be updated.

Note on MATCH-04 and MATCH-05: The Match table has `vibeScore` and `behavioralScore` columns which are stored as `null` for Phase 2 MVP (per CONTEXT.md deferred decisions). The architecture is in place; values will be populated in Phase 3.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client → GET /feed | JWT-authenticated; userId comes from validated token, not query param |
| Client → POST /swipes | JWT-authenticated; actorId from token, targetId from body (must validate) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-02-01 | Spoofing | POST /swipes body.targetId | mitigate | JwtAuthGuard ensures actorId = req.user.id from verified JWT, not from body; targetId is just a DB lookup target |
| T-02-02-02 | Tampering | Match user1Id/user2Id ordering | mitigate | `Math.min/Math.max` enforces user1Id < user2Id at app layer before every prisma.match.create call |
| T-02-02-03 | Elevation of Privilege | GET /feed returns other users' data | mitigate | Only returns fields needed for swipe card (no email, phone, telegramId); userId filter in query prevents self-inclusion |
| T-02-02-04 | Denial of Service | /feed with no city set | accept | Returns empty array (cityId: -1 matches nothing); handled gracefully in service |
| T-02-02-05 | Repudiation | Duplicate swipe | mitigate | 409 ConflictException on duplicate actorId+targetId prevents ballot-stuffing; unique constraint in schema is secondary defense |
</threat_model>
