# Phase 1 — UI Design Contract: Onboarding

> Visual and interaction contract for Phase 1 onboarding screens.
> Generated by gsd-ui-researcher. Consumed by gsd-planner, gsd-executor, gsd-ui-checker, gsd-ui-auditor.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Tailwind v4, CSS-first tokens) |
| Preset | not applicable |
| Component library | none (custom components only) |
| Icon library | inline SVG (20×20 or 18×18 viewBox, stroke-based, no external icon package) |
| Font | Geist Sans via `next/font/google` → `--font-geist-sans` |

**Source:** `front/app/globals.css`, `front/app/layout.tsx` — no shadcn, no third-party component library. All tokens defined as CSS custom properties in `:root` and mapped via `@theme inline`.

## Spacing Scale

Declared values (multiples of 4 only):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap, chip inner inline padding |
| sm | 8px | Gap between chips in a chip group |
| md | 16px | Horizontal page padding (`px-4`), gap between form fields |
| lg | 24px | Section spacing within a step card |
| xl | 32px | Spacing between step card and bottom CTA bar |
| 2xl | 48px | Top safe-area padding above progress bar |
| 3xl | 64px | Not used in this phase |

**Exceptions:**
- Touch targets (icon buttons, chips, toggles) — minimum 44px height/width for tap area
- Bottom CTA button — fixed 56px height (`h-14`) to meet minimum tap target
- Progress bar — 4px height (visual only, not a spacing unit)
- Chip height — 36px (`h-9`) for multi-select chips

**Layout container:** `mx-auto w-full max-w-md` (matches existing HomeView). Height: `h-[100dvh]` (dvh, not vh — required for Telegram WebView). No overflow at the root; step content scrolls internally if needed via `overflow-y-auto` on the content area.

## Typography

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Step heading | 24px (`text-2xl`) | 700 (bold) | 1.2 | Main question per screen, ≤36 characters |
| Body / description | 16px (`text-base`) | 400 (normal) | 1.5 | Supporting copy under heading, option labels |
| Label / chip | 14px (`text-sm`) | 500 (medium) | 1.4 | Chip button labels, form field labels, hint text |
| Display (DoneStep only) | 32px (`text-4xl`) | 700 (bold) | 1.1 | Success heading "Профиль создан!" |

**Note on 3 weights:** This spec uses 400/500/700 — one more than the recommended 2. Weight 500 (`font-medium`) is scoped exclusively to `text-sm` elements (chips, labels) where the contrast with `font-normal` would be insufficient at small size. It is not used at `text-base` or above, keeping the reading hierarchy clean.

**Font stack:** `var(--font-geist-sans, system-ui), Arial, Helvetica, sans-serif`

**Rules:**
- Step headings: ≤36 characters (from PROJECT.md constraint). Never wrap to 3 lines.
- All body text: `text-(--text)` → `#14140f`
- Hint / muted text: `text-(--text-muted)` → `#6f6f68`
- White text used only on dark overlays (photo card gradient zone — existing pattern from ProfileCard)
- No italic, no underline for UI elements

## Color

| Role | Value | CSS Token | Usage |
|------|-------|-----------|-------|
| Dominant (60%) | `#f6f6f1` | `var(--bg)` | Page background, step container background |
| Secondary (30%) | `#ffffff` | `var(--surface)` | Step card surfaces, input fields, chip default background |
| Secondary alt | `#f0efe9` | `var(--surface-2)` | Progress bar track, inactive states, scenario card hover |
| Accent (10%) | `#c8f36a` | `var(--accent)` | See reserved list below |
| Destructive | `#ff6b85` | `var(--rose)` | Destructive actions only (none in Phase 1 — reserved) |
| Lavender | `#d6cffa` | `var(--lavender)` | Selected chip background (alternative to accent for multi-select) |

**Accent (`#c8f36a`) reserved for:**
1. Primary CTA button background (the single forward-action button on each step)
2. Selected scenario card border/indicator
3. Progress bar fill
4. Quiz answer chip in selected state (active A or B)
5. DoneStep checkmark icon background

**Accent is NOT used for:** secondary buttons, disabled states, icon buttons, body text, borders of unselected elements.

**Text on accent:** `var(--text-on-accent)` → `#14140f` (near-black). Always use this token when text sits on the lime background.

**Selected chip (multi-select):** Use `--lavender` (`#d6cffa`) background + `--text` text for district chips and vibe tag chips. Reserve `--accent` for primary action confirmation (the CTA) to maintain clear hierarchy.

**Disabled state:** `opacity-50` on the primary CTA when the step's required selection has not been made. Do not change the button's background color for disabled — opacity only.

**Source:** `front/app/globals.css` — all tokens confirmed present.

## Screen Inventory

All screens share the same base layout shell:

```
┌─────────────────────────────────┐  h-[100dvh]
│  [Progress bar]                 │  4px, top of safe area
│                                 │
│  [Step content area]            │  flex-1, overflow-y-auto
│    [Heading]                    │  text-2xl font-bold
│    [Description / hint]         │  text-base text-muted mt-2
│    [Interactive element(s)]     │  mt-6
│                                 │
│  [Primary CTA button]           │  fixed bottom, h-14, w-full
└─────────────────────────────────┘
```

**Telegram BackButton API:** `show()` when `step > 0`, `hide()` when `step === 0`. No in-app back arrow rendered — Telegram's native header button handles back navigation.

**PATCH call timing:** Each CTA tap triggers the PATCH/POST for the current step, then advances `step`. Show a loading spinner inside the CTA button (replace label text with a 20px circular spinner) during the API call. On error, show an inline toast (see Error States section).

### Screen 1 — LocationStep

**Route:** `/` with `step === 1`
**Requirement:** ONBOARD-02

**City dropdown — spec:**
- `rounded-2xl bg-surface px-4 h-14 w-full` — same height as CTA
- Right chevron icon (16×16 inline SVG, `text-muted`)
- On tap: opens a native-style bottom sheet (or `<select>` with `appearance-none` styled — see note)

- Section label: "Районы" — `text-sm font-medium text-muted mt-4 mb-2`

- Chip: `rounded-full bg-surface h-9 px-4 text-sm font-medium text-(--text) transition-colors`
- Chip shadow: `var(--shadow-button)` (light, existing token)
- Selected chip: `bg-lavender text-(--text)` (replaces bg-surface)
- Multi-select: any number of districts can be selected
- Max display: all districts shown; if >12, wrap — no truncation
- If city has no districts in seed: hide district section entirely

**Primary CTA:** «Продолжить» — disabled until city selected. Districts are optional.

### Screen 2 — BudgetStep

**Route:** `/` with `step === 2`
**Requirement:** ONBOARD-03
**Telegram BackButton:** visible

**Layout:**
```
[Progress: 2/6]

Heading: "Какой у тебя бюджет?"

```

**Budget inputs — spec:**
- Two `<input type="number">` side by side: `от [____] до [____] ₽`
- Container: `flex items-center gap-3`
- Each input: `flex-1 rounded-2xl bg-surface h-14 px-4 text-base text-(--text) text-center`
- Label "от" and "до" outside the inputs, `text-sm text-muted`
- Currency symbol "₽" inside input suffix or after the field — `text-sm text-muted`
- Placeholder: "20 000" / "50 000"
- Validation: `budgetMin ≥ 5000`, `budgetMax ≥ budgetMin`. Show inline error text (14px, `var(--rose)`) below the row if violated on CTA tap.

**Date inputs — spec:**
- Move-in date: `<input type="date">` — styled identically to budget input but full-width. Label above: "Дата въезда" (`text-sm font-medium`)
- Stay duration: `<select>` styled like city dropdown. Options: "1 месяц", "2 месяца", "3 месяца", "6 месяцев", "1 год", "Не знаю". Label above: "Срок проживания"
- Both fields: optional. If empty, send `null` in PATCH.

**Primary CTA:** «Продолжить» — always enabled (budget/dates are guideline values, not hard blocks). Validation shows inline errors but does not block submit if budgetMin > 0 and budgetMax >= budgetMin.

## Motion & Transitions

| Interaction | Animation | Duration | Easing |
|-------------|-----------|----------|--------|
| Step forward (0→1→...→6) | Slide left: current exits `translateX(-100%)`, new enters from `translateX(100%)` | 280ms | `ease-out` |
| Step back (Telegram BackButton) | Slide right: current exits `translateX(100%)`, new enters from `translateX(-100%)` | 280ms | `ease-out` |
| Quiz question advance | Same slide-left as step forward | 250ms | `ease-out` |
| Option chip tap | `scale(0.97)` → `scale(1)` spring | 150ms | `cubic-bezier(0.34, 1.56, 0.64, 1)` |
| Scenario card select | `ring` appears + scale `1.01` | 120ms | `ease-out` |
| Toggle switch | Background color transition | 200ms | `ease-in-out` |
| Done checkmark entry | Scale `0 → 1` spring | 400ms | `cubic-bezier(0.34, 1.56, 0.64, 1)` |
| CTA button tap | `scale(0.97)` active state | 100ms | `ease-out` (via `active:scale-97`) |
| Loading spinner in CTA | Continuous rotation | 700ms | `linear` (CSS `animate-spin`) |
| Chip deselect (tag limit) | `opacity-40` on non-selected | 150ms | `ease-out` |

**Step transition implementation:** Wrap `OnboardingFlow`'s step content in a keyed container. Use CSS-only approach: `transition: transform 280ms ease-out` with JS toggling classnames. No Framer Motion or external animation library.

**Haptics:** Trigger `haptic('light')` on every tap interaction (scenario card, chip, toggle). Trigger `hapticNotify('success')` on DoneStep mount. Uses existing `haptic()` / `hapticNotify()` from `shared/lib/telegram`.

## Accessibility & Platform Constraints

**Telegram WebView constraints:**
- `h-[100dvh]` mandatory — `h-screen` fails in Telegram due to collapsing header
- `overscroll-behavior: none` already in globals.css body rule — preserve this
- `-webkit-tap-highlight-color: transparent` already in globals.css — preserve this
- `user-select: none` on body already set — interactive elements inside forms (input, select) will still work as browser overrides this for form controls
- `touch-action: none` — do NOT set on scrollable content areas inside steps (only on drag targets like SwipeCard). Step content area uses normal scroll.

**Minimum touch targets:**
- All buttons, chips, toggles: minimum 44×44px tap area
- Chip visual height is 36px but tap area extends to 44px via `min-h-[44px]` on the chip's touch wrapper (or `py-1.5` padding)
- CTA button: 56px height (`h-14`) — exceeds minimum

**Input behavior:**
- `<input type="number">` on mobile shows numeric keypad — correct for budget
- `<input type="date">` shows OS date picker — acceptable for Phase 1
- `<select>` shows OS picker — acceptable for Phase 1
- On iOS WebView: virtual keyboard pushes layout — use `pb-safe` or ensure CTA is not obscured. The CTA is fixed at bottom; when keyboard opens, it may be obscured. Workaround: `fixed bottom-0` + `pb-4` with conditional `pb-[env(safe-area-inset-bottom,16px)]`

**Screen reader / a11y:**
- All icon buttons: `aria-label` required (pattern from existing HomeView `RoundIconButton`)
- Toggle switches: `role="switch"`, `aria-checked` on the toggle input
- Progress bar: `role="progressbar"`, `aria-valuenow`, `aria-valuemax`
- Chip buttons: `role="checkbox"` for multi-select, `aria-checked`; `role="radio"` for single-select
- Quiz options: `role="radio"` within a `role="radiogroup"`
- Error messages: `role="alert"` so screen readers announce on inject

**No back button rendering:** Telegram BackButton is the system back mechanism. Do NOT render an in-app back arrow — this would conflict with Telegram's native UX. The BackButton API is called programmatically via `Telegram.WebApp.BackButton.show()` / `.hide()`.
