## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| frontend → POST /onboarding/quiz | 10 quiz answers sent in one request; backend validates answerValue 0–1 |
| Telegram initDataUnsafe → name field | first_name comes from Telegram SDK; used as UI default only, not trusted for auth |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | QuizStep timer (300ms) — user could intercept and submit arbitrary answers | accept | answerValue on frontend is constrained to optionA.value or optionB.value from the constant. Backend @IsNumber @Min(0) @Max(1) rejects out-of-range values anyway. |
| T-04-02 | Information Disclosure | initDataUnsafe.user.photo_url used for profile photo | accept | Photo URL is from Telegram's own CDN. Displayed in-app only. Not stored in DB directly — PATCH /onboarding/profile sends empty photoUrls; backend uses stored telegramPhotoUrl from auth upsert. |
| T-04-03 | Tampering | More than 3 vibe tags selected (client-side limit) | mitigate | Backend ProfileDto.vibeTagIds has @ArrayMaxSize(5) — allows up to 5 for flexibility. Frontend enforces 3 as UX limit. Backend doesn't enforce 3 exactly (acceptable). |
| T-04-04 | Denial of Service | getVibeTags() called on every ProfileStep mount | accept | Single DB read of 22 rows. Cancellation pattern prevents stale state. No debounce needed. |
</threat_model>
