<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → API | HTTP requests from frontend (or any client) to NestJS |
| JWT → user identity | JwtAuthGuard extracts userId from JWT — all writes scoped to that userId |
| DTO → Prisma | class-validator validates input before it reaches Prisma operations |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | PATCH /onboarding/* — user writes to another user's data | mitigate | `@CurrentUser() user: { id: number }` — userId comes from JWT, not request body. All `where: { id: userId }` use JWT-extracted ID only. |
| T-02-02 | Tampering | POST /onboarding/quiz — answerValue outside 0–1 | mitigate | `@IsNumber() @Min(0) @Max(1)` on QuizAnswerDto.answerValue. Global ValidationPipe with forbidNonWhitelisted rejects extra fields. |
| T-02-03 | Tampering | PATCH /onboarding/location — districtId FK pointing to non-existent district | accept | Prisma FK constraint throws a P2003 error, bubbles as 500. Acceptable for Phase 1 (frontend uses seeded IDs only). |
| T-02-04 | Tampering | Mass assignment via extra body fields | mitigate | `forbidNonWhitelisted: true` in global ValidationPipe already rejects unknown fields. |
| T-02-05 | Information Disclosure | GET /onboarding/status — returns user data | accept | Endpoint requires valid JWT; returns only the authenticated user's own data. No cross-user exposure. |
| T-02-06 | Spoofing | JWT forgery | accept | JwtService with `JWT_SECRET` handles verification. Config.getOrThrow fails fast if secret missing. |
</threat_model>
